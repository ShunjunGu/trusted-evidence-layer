# 检索分在重排前按批次归一化

Status: accepted (2026-11-07)

重排把检索分、信任分与冲突惩罚放在同一尺度上相加。不同检索器返回的分数尺度不兼容：cosine 在 `[0,1]`，BM25 无上界，部分引擎为负。直接把原始检索分与信任分相加，会让无界尺度淹没信任与冲突信号。因此：整批分数已在 `[0,1]` 时原样使用；否则整批做 min-max 归一化到 `[0,1]`；全批等值且超出 `[0,1]` 时取 `0.5`。每条 evidence 同时报告原始 `retrieval_score` 与参与重排的 `retrieval_normalized`。

## Considered Options

- **clamp 到 [0,1]**：会把 BM25 的 2.5 与 8.0 都压成 1.0，丢失检索区分度。
- **始终 min-max**：会改变已经归一化的引擎（cosine/embedding）的语义，且让所有重排都变成批次相对。
- **单调压缩 `s/(1+s)`**：对有界分数同样造成不必要的形变。

## Consequences

- 当输入未落在 `[0,1]` 时，`rerank_score` 是批次相对的；报告暴露 `retrieval_normalized` 以便审计。
- 单候选且分数超出 `[0,1]` 时没有跨度，归一化为 `0.5`（排序不受影响）。
- 同一份文档在不同候选集中的 `rerank_score` 不保证可比；跨批次比较应看原始 `retrieval_score` 与各项分项。
